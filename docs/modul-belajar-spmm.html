1. Cara berpikir seperti pembangun aplikasi

Aplikasi adalah cara mengubah masalah menjadi alur kerja yang bisa dilakukan komputer.

MasalahSolusi di SPMM
Data pendaftar tercecer di chatForm pendaftaran menyimpan data ke database.
Petugas sulit mengetahui statusStatus lead, pembayaran, dan pemberkasan ditampilkan di dashboard.
Affiliator tidak tahu komisiKode referral menghubungkan pendaftar dan perhitungan komisi.

Biasakan bertanya: siapa pengguna fitur ini? data apa yang masuk? proses apa yang terjadi? hasil apa yang keluar? pertanyaan ini menjadi dasar DFD dan ERD.

2. Apa itu bahasa pemrograman?

Bahasa pemrograman adalah bahasa formal untuk memberi instruksi kepada komputer. Seperti bahasa manusia memiliki kosakata dan tata bahasa, bahasa pemrograman memiliki sintaks dan aturan tipe data.

Contoh sederhana

nama = "Budi"
if nama == "Budi":
    tampilkan("Halo, Budi")

Instruksi di atas menyimpan teks ke variabel nama, memeriksa kondisi, lalu menampilkan pesan.

Bahasa yang dipakai SPMM

  • PHP: bahasa utama backend Laravel.
  • SQL/PostgreSQL: bahasa untuk membaca dan mengubah database.
  • HTML: struktur halaman.
  • CSS: warna, ukuran, layout, dan efek visual.
  • JavaScript: interaksi di browser.
  • Blade: template HTML milik Laravel.
Backend berjalan di server dan mengatur aturan/data. Frontend terlihat di browser. Database menyimpan data agar tidak hilang ketika halaman ditutup.

4. Database: lemari arsip digital

Database adalah sistem teratur untuk menyimpan dan mencari data. PostgreSQL yang dipakai SPMM menyimpan data dalam tabel. Tabel mirip spreadsheet, tetapi memiliki aturan, relasi, index, dan transaksi.

Istilah inti

  • Entitas: sesuatu yang ingin dicatat, misalnya Pendaftar.
  • Atribut: sifat entitas, misalnya nama dan email.
  • Record/baris: satu data nyata, misalnya Pendaftar bernama Budi.
  • Kolom: tempat atribut disimpan.
  • Primary key: identitas unik, biasanya id.
  • Foreign key: kolom yang menunjuk ke primary key tabel lain.
  • Index: struktur bantu agar pencarian cepat.
  • Constraint: aturan seperti wajib diisi, unik, dan foreign key.

CRUD

Empat operasi dasar: Create membuat, Read membaca, Update mengubah, dan Delete menghapus data.

SELECT * FROM leads;
INSERT INTO leads (full_name, email) VALUES ('Budi', 'budi@email.com');
UPDATE leads SET lead_status = 'contacted' WHERE id = 1;
DELETE FROM leads WHERE id = 1;
Perhatian: DELETE menghapus data. Selalu gunakan filter yang tepat, backup, dan transaksi.

Jenis relasi

  • One-to-one (1:1): satu lead dapat memiliki satu profil mahasiswa.
  • One-to-many (1:N): satu campus memiliki banyak lead.
  • Many-to-many (N:N): mahasiswa dapat mengambil beberapa kelas dan kelas memiliki banyak mahasiswa; biasanya membutuhkan tabel penghubung.

6. ERD SPMM

ERD (Entity Relationship Diagram) menggambarkan entitas dan hubungan antarentitas sebelum database dibuat.

CAMPUS 1 ────────< N LEAD N >──────── 1 REFERRAL_PARTNER │ │ │ │ └─< STUDY_PROGRAM │ ├─< INVOICE ├─< AFFILIATE_COMMISSION │ ├─< STUDENT_PAYMENT │ │ ├─< DOCUMENT └─< AFFILIATE_NETWORK │ └─< REFERRAL_CONVERSION

Bacaan contoh: satu Campus dapat memiliki banyak Lead; satu lead boleh memiliki referral partner; satu referral partner dapat memiliki banyak komisi. ERD membantu mencegah data ganda dan hubungan yang membingungkan.

Langkah membuat ERD

  1. Tulis semua benda yang perlu disimpan.
  2. Ubah benda menjadi entitas/tabel.
  3. Tulis atributnya.
  4. Tentukan primary key.
  5. Tentukan relasi dan foreign key.
  6. Periksa apakah ada data yang berulang.

7. DFD SPMM

DFD (Data Flow Diagram) menggambarkan aliran data, bukan detail tabel. DFD menjawab: data datang dari siapa, diproses oleh apa, lalu disimpan atau dikirim ke mana.

DFD konteks

[Calon Mahasiswa] ── data pendaftaran ──► (SPMM) [Admin/Petugas] ── update/status ───────► (SPMM) [Affiliator] ── kode referral ──────────► (SPMM) (Pembayaran/Meta/WhatsApp) ─ event ─────► (SPMM) (SPMM) ── status, invoice, komisi ─────► pengguna

DFD level 1 pendaftaran

1. Terima Form → 2. Validasi → 3. Simpan Lead → 4. Buat Invoice │ └→ Hubungkan referral → Hitung milestone → Kirim notifikasi

Perbedaan penting: DFD fokus pada arus, ERD fokus pada struktur data. Keduanya saling melengkapi.

8. Arsitektur Laravel dan Filament

Request sampai response

URL /admin/leads ↓ route Filament Resource / Controller ↓ authorization + validation Model Lead + Eloquent query ↓ PostgreSQL ↓ Blade/Livewire menghasilkan HTML ↓ Browser admin
  • Route: alamat dan pintu masuk.
  • Middleware: pemeriksaan sebelum request diproses, misalnya login.
  • Model/Eloquent: cara PHP berbicara dengan tabel.
  • Migration: instruksi membuat/mengubah tabel.
  • Resource Filament: CRUD dashboard tanpa menulis seluruh UI dari nol.
  • Service: aturan bisnis kompleks seperti mesin komisi.
  • Job/Queue: pekerjaan yang dijalankan di belakang layar.
  • Notification: pesan kepada admin/user.

9. Membangun SPMM dari awal

Fase 1 — Analisis

  1. Tulis masalah bisnis dan siapa penggunanya.
  2. Buat daftar fitur: pendaftaran, campus, prodi, pembayaran, affiliate, laporan.
  3. Buat DFD konteks dan use case sederhana.
  4. Tentukan data yang perlu disimpan.

Fase 2 — Desain database

  1. Buat ERD.
  2. Buat migration tabel inti.
  3. Tambahkan foreign key, unique, index, dan status.
  4. Siapkan data awal dengan seeder yang jelas bernama.

Fase 3 — Backend

  1. Buat Model dan relasi.
  2. Buat Form Request untuk validasi.
  3. Buat Service untuk aturan bisnis.
  4. Buat Controller/Filament Resource.
  5. Tambahkan authorization sesuai role.

Fase 4 — Frontend

  1. Buat Blade layout.
  2. Tambahkan CSS responsif.
  3. Tambahkan JavaScript hanya jika interaksi membutuhkan.
  4. Uji desktop, tablet, dan HP.

Fase 5 — Integrasi dan operasi

  1. Uji payment callback, Meta lead, WhatsApp, dan email.
  2. Catat event penting dalam audit log.
  3. Atur queue worker, scheduler, backup, dan monitoring.
  4. Deploy setelah staging lulus.

10. Contoh alur fitur pendaftaran

  1. Calon mahasiswa membuka form.
  2. Browser mengirim POST dengan token CSRF.
  3. Laravel memvalidasi nama, email, WhatsApp, campus, dan program.
  4. Jika referral code ada, cari partner aktif.
  5. Buat Lead dalam transaksi database.
  6. Buat invoice atau jadwal pembayaran.
  7. Kirim notifikasi ke petugas.
  8. Admin menghubungi, mengubah status, dan memantau progres.
Transaksi database penting ketika beberapa tabel harus berhasil bersama. Jika salah satu langkah gagal, semua perubahan dapat dibatalkan sehingga data tidak setengah jadi.

11. Keamanan dan kualitas

  • Jangan menaruh password database di Git.
  • Gunakan hash password, bukan teks biasa.
  • Validasi semua input dari browser.
  • Gunakan authorization: tidak semua admin boleh melihat/mengubah semua data.
  • Gunakan CSRF, HTTPS, dan rate limiting.
  • Backup database sebelum migrasi/penghapusan.
  • Jangan menampilkan data sensitif di log.
  • Gunakan soft delete jika data perlu dipulihkan.

Checklist pengujian

  • Form valid dapat disimpan.
  • Form invalid menampilkan pesan yang jelas.
  • Referral code salah tidak membuat komisi.
  • Pembayaran callback idempotent: dipanggil dua kali tidak menggandakan pembayaran.
  • Role petugas tidak dapat membuka menu terlarang.
  • Halaman tetap nyaman di HP.
  • Backup dapat direstore di lingkungan uji.
